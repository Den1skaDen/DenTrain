# DenTrain — фитнес-приложение для Android

Kotlin · Jetpack Compose · Room · MVVM · Coroutines/Flow. Работает без интернета, с облачной синхронизацией Firebase.

## Запуск в Android Studio
1. Установите Android Studio (Koala 2024.1 или новее) — в комплекте JDK 17+.
2. `File → Open` → выберите папку проекта.
3. Дождитесь Gradle Sync (нужен интернет при первой синхронизации: Android Studio скачает Gradle 8.9 и библиотеки).
   Если студия предложит установить SDK Platform 34 — согласитесь.
4. Добавьте файл `google-services.json` от Firebase в папку `app/`.
5. Выберите эмулятор (Pixel, API 26+) или телефон с включённой отладкой по USB → `Run ▶`.

Если Sync выдаёт ошибку версий, откройте `File → Project Structure → Project` и поставьте Gradle 8.9 / AGP 8.5.2,
либо обновите версии плагинов в корневом `build.gradle.kts` до тех, что предлагает студия.

## Письма для подтверждения почты

Регистрация и повторная отправка вызывают функцию `sendVerificationEmail`. Она формирует ссылку Firebase Auth для текущего пользователя и отправляет шаблон `firebase-auth/verify-email.html` через Resend с адреса `noreply@mail.dentrain.ru`. Для кнопки используется страница `https://auth.dentrain.ru/verify/`.

### Cloudflare Workers Free без Blaze

Используйте отдельный сервисный аккаунт проекта `dentrain-9af07` с пользовательской ролью, которая содержит только `firebaseauth.users.sendEmail`. В Cloudflare задайте секреты `FIREBASE_EMAIL_SERVICE_ACCOUNT` (JSON ключ этого аккаунта) и `RESEND_API_KEY` (ключ с правом отправки для `mail.dentrain.ru`). Задайте переменную `FIREBASE_WEB_API_KEY` со значением `apiKey` из публичной конфигурации `https://auth.dentrain.ru/__/firebase/init.json`. Для развёртывания используйте конфигурацию `firebase-auth/wrangler.jsonc`.

Android по умолчанию обращается к `https://dentrain-email-verification.dorov-thletics.workers.dev/sendVerificationEmail`. Для другого Worker передайте его полный HTTPS-адрес с путём `/sendVerificationEmail` через Gradle-свойство `denTrainVerificationEndpoint`. Проверьте доставку при регистрации и повторной отправке, затем перейдите по ссылке из письма и убедитесь, что приложение видит подтверждённую почту.

Сброс пароля использует маршрут `/sendPasswordResetEmail` этого Worker и шаблон `firebase-auth/reset-password.html`. Он использует те же секреты Firebase и Resend. Для отдельного адреса Worker задайте `denTrainPasswordResetEndpoint` полным HTTPS-адресом с путём `/sendPasswordResetEmail`. При использовании Cloud Functions для подтверждения почты сброс пароля по умолчанию продолжает работать через Cloudflare Worker.

### Cloud Functions на Blaze

Перед выпуском Android-сборки проверьте, что на проекте `dentrain-9af07` включён Blaze, домен `mail.dentrain.ru` подтверждён в Resend, а обработчик `/verify/` доступен на `auth.dentrain.ru`. Сохраните ключ Resend с правом отправки для этого домена в Secret Manager, затем разверните функцию.

```powershell
firebase functions:secrets:set RESEND_API_KEY --project dentrain-9af07
firebase deploy --only functions:email-verification --project dentrain-9af07
```

Для этой схемы соберите Android с пустым свойством `-PdenTrainVerificationEndpoint=`.

## Структура проекта (`app/src/main/java/com/dentrain`)
| Файл / папка | Назначение |
|---|---|
| `MainActivity.kt` | Единственная Activity: читает тему из настроек и показывает навигацию |
| `DenTrainApp.kt` | Application + `AppContainer` (база, репозиторий, таймер — по одному экземпляру) |
| `data/Entities.kt` | Таблицы Room и связи (Workout → Exercise → SetResult) |
| `data/Daos.kt` | SQL-запросы (Flow — экраны обновляются сами) |
| `data/WorkoutRepository.kt` | Вся логика работы с данными: сохранение тренировки, подходы, закрепление, повтор, рекорды, настройки |
| `timer/RestTimer.kt` | Таймер отдыха по системным часам + будильник |
| `timer/TimerNotifier.kt`, `TimerAlarmReceiver.kt` | Вибрация, звук, уведомление |
| `ui/theme/Theme.kt` | Две акцентные темы × светлый/тёмный фон |
| `ui/components/` | Общие элементы: кнопка с градиентом, карточка, диалоги, выбор даты |
| `ui/navigation/AppNav.kt` | Нижняя панель из 4 вкладок и вложенные экраны |
| `ui/workout/` | Вкладка «Тренировка»: главный экран, редактор, выполнение |
| `ui/history/` | Вкладка «История» и просмотр тренировки |
| `ui/stopwatch/` | Вкладка «Секундомер» |
| `ui/records/` | Вкладка «Рекорды» (+ график) |
| `ui/settings/` | Настройки: акцент, фон, авто-таймер |

## Архитектура (MVVM + Offline First)
`Screen (Compose)` → `ViewModel` → `WorkoutRepository` → `DAO (Room)`.
Экран только показывает состояние и передаёт действия; ViewModel хранит состояние и проверяет ввод;
репозиторий — единственное место, которое знает о базе. Данные текут вверх через `Flow`,
поэтому, например, закрепление в «Истории» мгновенно появляется на вкладке «Тренировка».
Все данные сначала сохраняются локально (Offline First), а затем синхронизируются с Firebase.

## База данных
- `workouts` — тренировка: название, дата, день недели, статус (запланирована / идёт / завершена), текущее упражнение.
- `exercises` — упражнения тренировки (**план**: подходы, повторы, вес), связь по `workoutId`, каскадное удаление.
- `set_results` — выполненные подходы (**факт**: повторы, вес, секунды), связь по `exerciseId`.
- `pinned_workouts` — только ссылка на тренировку (дубликатов нет).
- `records` — личные рекорды (вес, повторы, дата, комментарий) в точности как введены.
- `settings` — одна строка: акцент, фон, время отдыха, авто-таймер, будильники.

Тренировка — самостоятельная запись. Новое занятие никогда не меняет историю; «Повторить» создаёт **копию** как новую запланированную тренировку.

## Тренеры, заявки и доставка

- В Firestore хранится одна карточка на пару «спортсмен — тренер». Повторная отправка обновляет карточку через час или позже. Учитываются максимум три попытки за скользящие 24 часа. Принятие привязывает ученика, закрывает карточку и записывает уведомление одной транзакцией.
- Ожидающая заявка хранится семь дней. После принятия, отказа или отзыва карточка сразу исчезает из очереди. Техническая запись остаётся до истечения лимита отправки. Настройки TTL находятся в `firestore.indexes.json`. Срок хранения новых уведомлений — 90 дней.
- Тренировка и уведомление ученику записываются одной операцией. Офлайн-запись ждёт сети в локальном хранилище Firestore. Android планирует фоновую отправку при подключении. Тренер или администратор получает одно подтверждение в приложении, когда ученик сохранил тренировку в дневник.
- Журнал администратора показывает смену роли или тренера, удаление профилей и клубов, а также назначение тренировок администратором. Проверка Firestore связывает действие и запись журнала в одной операции.

Новые APK, правила и индексы рассчитаны на одну версию протокола. Публикуйте их согласованно, поскольку предыдущая версия Android-клиента пишет заявки и назначения по старой схеме. До миграции запустите проверку количества документов. Добавляйте `--apply`, когда старые клиенты больше не записывают заявки и новые правила уже опубликованы.

```powershell
node firebase-tests/migrate-trainer-requests.cjs "<папка установленного пакета firebase-tools>"
```
